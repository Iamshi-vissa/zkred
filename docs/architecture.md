# Architecture

```
 University (off-chain)                         Ethereum
 ─────────────────────                          ────────
 issuer key ──signs RootUpdate(root, epoch)──▶  Registry ◀── owner (Ownable2Step):
 Merkle tree of Poseidon leaves                   │  roots + history       rotateIssuer, revokeRoot
                                                  │ isKnownRoot(root)
 Student (off-chain)                              ▼
 secrets + Merkle path ──Groth16 proof──────▶  CredentialGate ──verifyProof──▶ CredentialVerifier
   (circuits/credential.circom)                   │ nullifiers, date, scope,       (generated by snarkjs)
                                                  │ credentialType, msg.sender
                                                  └──mint 100 ZKRED──▶ ZKredToken (gate = only minter)
```

## Contracts
| Contract | Responsibility | Built on |
|---|---|---|
| `Registry` | Stores issuer-signed roots; strict epochs; 30-epoch root history; owner can rotate the issuer key and revoke roots | OZ `EIP712`, `ECDSA`, `Ownable2Step` |
| `CredentialGate` | Checks root, nullifier, date; fixes scope, credentialType and recipient; verifies the proof; marks the nullifier; mints the reward | — |
| `ZKredToken` | ERC-20 "ZKred"/"ZKRED". Deployed **by** the gate, which gets `MINTER_ROLE`; no admin role exists, so no other minter can ever be added | OZ `ERC20`, `AccessControl` |
| `CredentialVerifier` | Groth16 verification over BN254 (EVM precompiles 0x06–0x08); rejects public inputs ≥ r | generated by `npm run setup` |
| `DateLib` | `block.timestamp` → YYYYMMDD | vendored BokkyPooBah DateTime (`contracts/vendor/`) |

## `CredentialGate.claim(a, b, c, root, nullifierHash, currentDate)`
| Check | Why | Revert |
|---|---|---|
| `registry.isKnownRoot(root)` | Membership is only meaningful in a root the issuer published, recently, and not revoked | `UnknownRoot` |
| `!nullifierUsed[nullifierHash]` | One claim per student per gate | `NullifierAlreadyUsed` |
| `currentDate` ∈ {today, yesterday} (UTC) | The circuit has no clock. Yesterday tolerates a proof made just before midnight. Tomorrow is **not** allowed, since that would let someone claim the day before turning 18. | `InvalidDate` |
| public signals assembled by the contract: `scope` (immutable), `credentialType` (immutable), `recipient = msg.sender` | The prover can't choose them, so cross-gate / cross-chain replay and front-running fail | `InvalidProof` |
| `verifier.verifyProof(...)` | Groth16 check; also rejects inputs ≥ r (no `nullifier + r` aliasing) | `InvalidProof` |

Effects happen after all checks: nullifier marked, `Claimed(recipient, nullifierHash)` emitted, then 100 ZKRED minted.

`scope = keccak256(abi.encode(block.chainid, address(gate), actionId)) mod r`, so the
same student gets unlinkable nullifiers at different gates.

## Registry
- `updateRoot(root, epoch, signature)`: anyone may relay; the EIP-712 signature
  over `RootUpdate(uint256 root, uint64 epoch)` (domain: name "ZKred Registry",
  version "1", chain id, registry address) must recover to `issuer`. Epochs must
  be exactly `current + 1`, so an old signature can never be replayed.
- A root is valid for 30 epochs after it was published, so proofs made just
  before a root rotation still work.
- `rotateIssuer(newIssuer)` (owner): the old key immediately stops working,
  including any updates it signed in advance.
- `revokeRoot(root)` (owner): the root stops verifying immediately and can never
  be re-published, even with a valid issuer signature. It can also be revoked
  before it is ever published.
- The owner **cannot** publish roots itself. Publishing is the issuer's job, and
  the owner is only the incident-response authority.
